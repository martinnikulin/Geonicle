# Логика БД и код

Решение пользователя (2026-11-01): триггеры и хранимые процедуры остаются в БД. Перехвата `SaveChanges` в коде нет (ни собственного, ни библиотеки EntityFrameworkCore.Triggered: пробовали и отказались, пока работают триггеры БД). В код переносится только то, что пользователь явно убирает из БД.

DDL (изменение и удаление триггеров и процедур, обновление скриптов в `gdb/`) выполняет пользователь.

## Перенесено в код

| Из БД | Что делает | Где в коде |
|---|---|---|
| `AfterInsertHoles`: `INSERT INTO Survey (BoreholeId, Depth, Dip, Azimuth) SELECT BoreholeId, 0, 0, 0` | новая скважина получает нулевой замер | `BoreholesService`: при создании строки в гриде в `Surveys` сразу добавляется замер 0/0/0, он виден в «Инклинометрии» до сохранения |

Скважины, созданные не из грида «Скважины» (например, импортом), нулевой замер в коде не получают.

## Убирается из БД без замены

| Из БД | Решение |
|---|---|
| `AfterInsertHoles`: `INSERT INTO dbo.LineHoles (BoreholeId, LineId) SELECT BoreholeId, 0` | пользователь убирает из триггера, в коде не создаётся |

## Остаётся в БД

- `AfterInsertHoles`: запись `ChangedRecords('Survey', BoreholeId)`.
- `AfterUpdateHoles`, все остальные триггеры, метки `DateCreated`/`DateModified` (проставляет сервер БД, чтобы не писать время клиентских компьютеров).
- Все хранимые процедуры (включая тяжёлые расчётные `Reserves*`, `CalcBlock*`, `CalcComposites`), функции и представления.
